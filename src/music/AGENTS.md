# 음악 담당 작업 규칙

## 적용 범위
- 이 AGENTS.md의 자동 적용 범위는 `src/music/` 하위다. 저장소 전체 규칙이 아니다.
- 문서는 이 디렉터리 직속에, 향후 Python 수집 코드는 `collectors/`, SQL은 `db/`, TypeScript 추천은 `algorithm/`에 둔다.
- 원본 데이터·로컬 검증 결과는 담당 루트의 `.local/`에 둔다. 기존 분석 스크립트 `src/music/.local/music-muse/analyze.py`도 이동 지시에 따라 보존한다.
- 사용자 지시와 상위 지침을 우선하며 팀원의 작업·기존 변경을 보존한다.

## 작업 경계
- 담당 문서·SQL·코드는 사용자에게 허용된 작업 범위에서 수정한다. 기존 팀원 기능·공용 의존성·잠금 파일은 수정하지 않는다.
- 루트 관리 문서를 신설하거나 팀 문서를 덮어쓰지 않는다. 대상이 이미 있으면 먼저 확인한다.
- `07_Main_Development_Workflow_v1.2.md`를 수정·이동·삭제하지 않는다.
- 공유 PostgreSQL 접속·변경, 허용되지 않은 신규 데이터 수집·적재, Git commit/push를 수행하지 않는다. 명시적으로 허용된 격리 로컬 검증에는 합성 fixture를 사용하며 기존 로컬 데이터는 보존한다.
- 후속 구현은 해당 작업에서 허용된 범위만 수행한다. 계획 기재 자체를 실행 권한으로 해석하지 않는다.

## 진행 방식
- PROJECT → PLAN → STATUS → 필요한 SPEC/코드로 범위를 좁혀 확인한다.
- 이미 확인했고 변경되지 않은 파일은 다시 읽지 않는다. 전체 저장소 탐색과 장문 보고를 피한다.
- 사실, 제안, 미확정 항목을 구분하고 비밀키·접속 문자열·원본 대량 데이터를 문서에 넣지 않는다.
- 설계는 SPEC, 일정·완료 조건은 PLAN, 결과·문제·다음 작업은 STATUS에 기록한다.
- 경로는 별도 표시가 없으면 저장소 루트 기준이다. `.local/`과 비밀정보는 루트 `.gitignore` 규칙으로 추적에서 제외한다.
- 후속 코드 작성은 기존 strict TypeScript, ESM/NodeNext와 `.js` import 경로 관례를 따른다.

## 검증
- 문서 전용 변경: 링크·요구사항·변경 파일 범위 확인. 앱·DB를 실행하지 않는다.
- 후속 구현: `pnpm build`, 정규화·매칭·VIEW·추천의 의미 있는 테스트 수행.
- DB 실행 검증은 별도로 허용된 테스트 환경에서만 수행하고 미실행 검증은 명시한다.
- 완료 보고는 생성/수정 파일, 검증 결과, 다음 작업만 간결하게 전달한다.
