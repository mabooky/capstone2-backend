# 음악 모듈 작업 규칙

이 지침은 `src/music/`에 적용한다. 사용자 지시와 상위 지침을 우선한다.

- 진입 문서는 README.md, 계약은 SPEC.md, 출처는 SOURCES.md 및 데이터셋 README다.
- 개발 브랜치는 실행·운영 준비·핵심 검증용 26개 파일을 유지한다. 연구 자료는
  `archive/music-research-20261027`의 기준 커밋 `6eb1f96efa37bc1785f925a24039f46b7026fe3d`에 보존한다.
- 기존 추천 알고리즘, SQL 정규화 공식, 데이터셋 songs.jsonl/normalization.json/manifest.json과
  과거 연구 검증 해시를 임의로 바꾸지 않는다. 변경이 필요하면 별도 버전과 승인을 받는다.
- 원본·백업 PGlite를 엔진으로 열지 않는다. READ ONLY도 파일 불변을 보장하지 않는다.
  테스트는 공유 데이터셋 또는 인자 없는 `new PGlite()` 합성 메모리 DB만 사용한다.
- `.local/`의 코드·데이터·컴파일 산출물과 테스트 이름 제외 필터에 의존하지 않는다.
  원본 경로를 환경변수나 임시 테스트 입력으로 연결하지 않는다.
- 수집·적재·verified 전환·공유 DB 접속·Git commit/push는 명시적으로 허용된 작업만 수행한다.
- 팀원 코드·실행 스크립트·공용 타입을 보존하고 필요한 최소 범위만 변경한다.
  strict TypeScript, ESM/NodeNext와 `.js` import 관례를 따른다.
- `.local/`, 인증정보, DB/WAL·체크포인트, 빌드 산출물은 추적하지 않는다.
- 코드 변경 후 README의 빌드·강화 타입 검사·4개 명시적 테스트 파일·메모리 SQL 검사를 실행한다.
  검증하지 못한 항목은 보고하고 원본 DB 접근으로 우회하지 않는다.
- 실제 Spotify 유효성·재생·추천 품질과 데이터셋의 형식/해시 검증을 구분한다.
